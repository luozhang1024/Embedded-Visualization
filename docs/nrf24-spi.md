# STM32 ↔ nRF24L01：SPI 是同时交换

实验使用 Mode 0（CPOL=0、CPHA=0）、8 位、MSB first。STM32 产生 SCK，两端在同一个上升沿采入数据、在下降沿准备下一位。

## 信号关系

| 信号 | 驱动方向         | 用途                                        |
| ---- | ---------------- | ------------------------------------------- |
| SCK  | STM32 → nRF24L01 | 双方移位与采样所需的时钟                    |
| MOSI | STM32 → nRF24L01 | 发送命令、地址或数据                        |
| MISO | nRF24L01 → STM32 | 同时返回 STATUS 或目标数据                  |
| CSN  | STM32 → nRF24L01 | 低电平选中，整个事务期间保持低              |
| CE   | STM32 → nRF24L01 | 无线工作模式控制；本实验保持低，与 CSN 分开 |

真实硬件还需正确供电、共地和电平匹配；页面展示逻辑协议，不作为完整接线图。CSN 高时从机释放 MISO，页面显示 `Z`。

## `state = NRF24L01_Read_Reg(STATUS)`

以 STATUS 快照为 `0x2E` 为例：

| 同一组时钟 | MOSI 发出                                        | MISO 同时返回              | 驱动含义                             |
| ---------- | ------------------------------------------------ | -------------------------- | ------------------------------------ |
| 第 1–8 个  | `R_REGISTER \| STATUS` = `0x00 \| 0x07` = `0x07` | `STATUS = 0x2E`            | 发读命令；同时得到命令期间的状态     |
| 第 9–16 个 | `0xFF` 占位字节                                  | `STATUS 寄存器内容 = 0x2E` | 持续产生时钟，把目标寄存器移入 STM32 |

CSN 在这 16 个时钟期间一直为低，结束后拉高。常见 `Read_Reg` 封装返回第二个接收字节，所以 `state = 0x2E`。第一字节也收到 STATUS，但不少驱动忽略它。

**`0x07` 是地址组成的读命令，不是向 STATUS 写入数值。** 写寄存器使用 `W_REGISTER`（`0x20`）命令；STATUS 中的中断位还有写 1 清除语义，本实验不模拟寄存器写入。

## 读 CONFIG，分清两次返回

CONFIG 固定为教学示例 `0x0B`，不表示芯片复位默认值：

| 字节阶段 | MOSI                                 | MISO             |
| -------- | ------------------------------------ | ---------------- |
| 读命令   | `0x00`（R_REGISTER + CONFIG 地址 0） | `0x2E`（STATUS） |
| 数据     | `0xFF`（占位）                       | `0x0B`（CONFIG） |

两个字节期间都在同时发和收，只是驱动对收到的字节有不同用途。

## `0xFF` 为什么有两种含义？

- **CSN 拉低后的首字节**：`0xFF` 是 nRF24L01 的 NOP 命令。发送 8 个时钟，就能读回 STATUS，不需要第二个字节。
- **R_REGISTER 后的数据阶段**：`0xFF` 是占位字节。从机已经进入寄存器读取阶段，忽略 MOSI 内容；改为 `0x00` 也不会改变这个事务的寄存器返回值。

占位发送使 SPI 控制器继续输出时钟。其他器件可能有不同要求，应以具体协议为准。

## 页面操作

默认进入**故事模式**。点击“演示下一幕”，到下一动作或字节完成处会自动停下；点击“敲一下时钟”，两条数据线各采入一位。需要先通过下一幕选中芯片；数据收全后也需通过下一幕结束片选。暂停时双方接收进度不再变化。

故事下方的 `rx[0]`、`rx[1]` 和 `state` 分开显示：收到第一个字节并不表示函数已经返回。STATUS 两次返回数值相同容易混淆，可点击“换成读 CONFIG”立即对比。NOP 故事只有四幕，不会出现第二个数据字节。

可展开同步时序，也可切换到**真实信号**视图；视图切换会暂停播放、保留当前事务位置。下面的字节跳转按钮位于真实信号视图中：

1. 选择 SPI，默认进入 STM32 ↔ nRF24L01。
2. 点击“命令 · 8 个时钟”，跳到命令字节最后一个采样沿；MISO 已收到 STATUS。
3. 点击“数据 · 8 个时钟”，观察第二个完整字节。此时 CSN 尚未抬高，右侧显示“待拉高 CSN”。
4. 再单步结束事务，查看函数返回值。
5. 切换 CONFIG、NOP 或占位字节，对比返回内容与时钟数。

上方收发寄存器逐位填充，下方两行数据使用同一位号高亮，波形同步绘制四根信号。参数改变会重置进度；时间轴可以回看任意采样沿。

## 模型与参考

协议依据 Nordic **nRF24L01+ Product Specification** 的 _SPI interface_、_SPI commands_ 和 _Register map_ 章节。示例也适用于这里涉及的 nRF24L01 基本 SPI 读命令。

STATUS 为事务期间不变的快照，不模拟无线事件或异步中断；`0x4E` 表示 RX_DR 仍置位但 RX FIFO 已空的教学状态。CONFIG 固定为 `0x0B`。不模拟 RF、FIFO、完整寄存器映射或硬件错误。HAL 示例需要初始化 `hspi1`、定义 CSN GPIO 宏并提供错误处理；失败路径的数值不能作为有效寄存器内容使用。
